# Data Collection

> 상태: **설계 단계**. 외부 API 실제 호출은 아직 한 번도 수행하지 않았다.

## TechSpecs API — 확인 상태

| 항목 | 내용 | 상태 |
| --- | --- | --- |
| 인증 | v5: `x-api-id`, `x-api-key` 헤더 | 문서 검색 결과 기반, **실호출로 확인 필요** |
| 검색 | `GET /v5/products/search?query=&brand=&category=&page=&size=` | 확인 필요 |
| 상세 | `GET /v5/products/{product_id}` | 확인 필요 |
| 응답 JSON 구조 | — | **확인 필요** (실제 응답 1건으로 확정 후 Zod 스키마 작성) |
| 무료 플랜 한도 | 검색 결과상 시간당 약 10회 | **대시보드에서 확인 필요** |
| DB 저장 · 캐싱 | 검색 결과상 상업적 저장은 별도 라이선스 필요 | **약관 원문 확인 필요** |
| 재배포 · 상업적 이용 | — | **약관 원문 확인 필요** |
| 이미지 저장 · 재사용 | 검색 결과상 별도 유료 | **약관 원문 확인 필요** |

위 항목이 확인되기 전까지 `TECHSPECS_LIVE_CALL_ENABLED=false`를 유지한다.

## 보호 장치

- 기본 비활성: 서버 시작 · 사용자 요청에서 외부 호출 없음
- `TECHSPECS_MAX_CALLS_PER_HOUR` 내부 상한 (기본 8)
- `external_product_mappings` 선조회로 동일 외부 ID 재호출 차단
- `data_sources.terms_policy`로 저장 허용 범위 제어 (원본 JSON 저장 기본 비활성)

## 수집 정책 (설정값)

- `MIN_RELEASE_DATE_DEFAULT=2023-11-01` (최근 3년)
- `MIN_RELEASE_DATE_EXTENDED=2022-11-01` (초기 수집 최대 범위, 이전 출시 제품 제외)
- 브랜드: Apple, Samsung / 카테고리: 스마트폰, 태블릿, 스마트워치

## 12단계 파이프라인

1. 외부 검색 → 2. 외부 ID 확인 → 3. 상세 요청 → 4. 브랜드 검증 → 5. 카테고리 검증 → 6. 출시일 검증 → 7. 모델 번호 확인 → 8. 중복 확인 → 9. 정규화 → 10. 출처 기록 → 11. 저장 허용 확인 → 12. 저장

검증 상태: `pending` · `verified` · `rejected` · `needs_review`. 불완전하거나 혼합 가능성이 있는 데이터는 자동 확정하지 않는다.

## 가격

가격 수집은 제품 수집과 독립적이다. 가격 공급자가 확정되기 전에는 크롤러나 임의 API를 구현하지 않으며, 관리자 등록 가격만 출처와 수집 시각을 함께 저장한다.
